Confidence: 0.90
- When `--color-primary` is light/near-white and would render white-on-white in dark mode (badges, warranty pills, CTA cards, timeline labels), the dark-mode fallback should be a neutral dark shade (e.g., `#1f221e`) rather than a blue/navy tint like `#0c2748`, which the user explicitly rejected; gate it behind an `isDark` flag threaded into the component. Confidence: 0.80
- Prefers reusable global CSS variables for theme-dependent colors - e.g., a `--color-chrome` defined in `globals.css` and the theme provider with separate light/dark values - rather than scattering hardcoded hex values across components; when a shade must change site-wide, the user asks to "make it globally" instead of fixing it per component, and expects checking whether an existing global variable already covers the shade before creating a new one. Confidence: 0.85
- On dark theme, button/link text must be white (not black) - avoid utility classes like `btn-cta` that force dark text in dark mode. Confidence: 0.70
- Prefers CTA/button colors to match the main theme (near-black `--color-primary`), replacing hardcoded off-brand colors like blue gradients. Confidence: 0.75
- Primary CTA buttons should link to the conversion/quote page (`/quote`) rather than placeholder `#` or stale data-driven hrefs. Confidence: 0.70
- When fixing a styling issue (color/theme, icon backgrounds, etc.), fix every occurrence site-wide — apply the fix retroactively to previously-completed sections and proactively to remaining/new ones ("fix the previous ones and also keep in mind for new ones") — not just the section first mentioned; the user gets annoyed when a fix lands in one place while other occurrences remain stale. Confidence: 0.90
- Card and table/surface backgrounds should be neutral dark surfaces (via `--color-surface`, `--color-surface-raised`, `--color-page-soft`, and `--color-border`), not bluish/navy rgba or hex values; when asked to fix a style, match the look of a named reference section (e.g., "Find Your Vehicle").
